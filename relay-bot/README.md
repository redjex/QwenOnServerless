# Relay bot (второй бот)

Этот бот ничего не считает. Его единственная задача — **эхо-пинг** для модели:
когда основной бот дописывает ответ, он кидает в общий групповой чат тик
`#qwen-tick user:<id>`, а этот бот возвращает его обратно. Основной бот не
получает собственные сообщения, но получает это эхо — и продолжает ответ.
Так продолжение работает целиком на Telegram Serverless, без VPS.

## 1. Установить и задеплоить (своим токеном второго бота)

```sh
cd relay-bot
npm install
npx tgcloud login          # токен CLI второго бота (app<id>:<secret>)
npx tgcloud push           # schema, lib (пусто), handlers
```

`tgcloud migrate` не нужен: таблиц нет.

## 2. Создать общий чат

1. Создай **группу** (не канал) и добавь в неё **обоих** ботов.
2. В @BotFather для **каждого** бота: `/setprivacy` → выбрать бота → **Disable**.
   После смены privacy **удали бота из группы и добавь заново** — иначе настройка
   не применится. Без этого боты не видят сообщения друг друга.
3. Отправь в группе команду `/relay` — основной бот запомнит чат и ответит
   «Ретранслятор включён». (Команда доставляется даже при включённом privacy.)

## 3. Проверка

- Задай вопрос основному боту в личке.
- В группе должны мелькать тики `#qwen-tick ...` (уведомления выключены).
- Ответ в личке должен дописываться сам, без VPS.

Выключить: `/relay_off` в группе. После этого снова работает VPS-воркер.

## Важно

- Если ретранслятор включён, VPS-воркер автоматически «встаёт» (видит
  `relay_group` и не берёт задачи), чтобы два драйвера не дрались за одну
  генерацию.
- Скорость: каждый кусок = один круг «основной бот → группа → релей → группа →
  основной бот», это добавляет ~0.5–1 с к порции по сравнению с VPS.
- Тики видны в группе; уведомления у них отключены. Группу можно замьютить.
